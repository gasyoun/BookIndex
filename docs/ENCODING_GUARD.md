# Проверка кодировки и моджибейка

_Created: 31-07-2026 · Last updated: 31-07-2026_

> Обновлено в тот же день (H2031): данные починены, легальное вхождение помечено, CI переведён на `--strict`.

Документация к [scripts/check_encoding.py](https://github.com/gasyoun/BookIndex/blob/main/scripts/check_encoding.py) — CI-проверке, которая ловит битую кодировку в исходниках, данных и документации. Редизайн детектора выполнен в рамках handoff H1482 моделью Opus 5 1M (`claude-opus-5[1m]`), 31-07-2026.

## Зачем понадобился редизайн

До 31-07-2026 детектор состоял из двух захардкоженных регулярных выражений, покрывавших ровно одну цепочку порчи: UTF-8-байты кириллицы, прочитанные как CP1252/Latin-1. Всё остальное проходило молча. При этом проект принимает внешний текст сразу несколькими путями — ответы Wikidata API ([scripts/align_authorities.py](https://github.com/gasyoun/BookIndex/blob/main/scripts/align_authorities.py)), расшифровки `.docx`/`.srt` с Яндекс-Диска ([scripts/ingest_transcripts.py](https://github.com/gasyoun/BookIndex/blob/main/scripts/ingest_transcripts.py)), issue-формы GitHub, — и каждый из них способен принести порчу другого класса.

## Метод

Моджибейк — это UTF-8-байты, прочитанные не тем однобайтовым кодеком. Поэтому детектор **обращает аварию вспять**, а не ищет сигнатуры: для каждого кандидата-кодека текст перекодируется обратно в байты, и в получившемся потоке ищутся серии корректных многобайтовых UTF-8-последовательностей.

Три и более такие последовательности подряд не могут появиться в правильно закодированном тексте — там для этого должны случайно совпасть шесть и более байт, — но в моджибейке они возникают по построению. Одна перекодировка и один проход регулярным выражением на кодек: стоимость линейна по размеру файла и не зависит от числа покрываемых классов порчи.

### Пороги и калибровка

| Параметр | Значение | Обоснование |
|---|---|---|
| `MIN_RUN` | 3 | Минимум последовательностей подряд. На корпусе из 5592 файлов (`app_data.json`, `data/modules/*.json`, собранные артефакты, `README.md`, `docs/**/*.md`) значения 2, 3 и 4 дают одинаковый результат — ноль срабатываний. |
| `MIN_LETTERS` | 3 | Восстановленный фрагмент должен быть буквами, а не пунктуацией или псевдографикой. |
| `PLAUSIBLE_LETTER_RANGES` | латиница, греческий, кириллица | Восстановление должно попадать в правдоподобный для корпуса алфавит. |

Фильтр правдоподобия — не косметика, а необходимое условие. Без него корпус даёт **девять ложных срабатываний**: обычные русские слова («углубляем», «принудительно») в кодировке CP866 случайно образуют корректный UTF-8 и «восстанавливаются» в иероглифы CJK. Русско-латинский корпус в CJK не восстанавливается никогда, поэтому проверка целевого алфавита убирает ровно этот класс ошибок и не трогает настоящую порчу.

## Что покрыто

| Класс порчи | Уровень | Как ловится |
|---|---|---|
| UTF-8 прочитан как CP1252 / Latin-1 | ошибка | обратная перекодировка |
| UTF-8 прочитан как CP1251 | ошибка | обратная перекодировка |
| UTF-8 прочитан как KOI8-R | ошибка | обратная перекодировка |
| UTF-8 прочитан как CP866 (DOS) | ошибка | обратная перекодировка |
| UTF-8 прочитан как Mac Cyrillic | ошибка | обратная перекодировка |
| Двойное UTF-8-кодирование | ошибка | проход Latin-1/CP1252 — именно этот след оставляет цепочка |
| Некорректный UTF-8, NUL-байты | ошибка | декодирование файла |
| Потеря обязательной фразы | ошибка | `REQUIRED_PHRASES` |
| Символы замены U+FFFD | **предупреждение** | прямой поиск |

**Почему U+FFFD только предупреждение.** Легальный код цитирует этот символ намеренно: [v3_app.js](https://github.com/gasyoun/BookIndex/blob/main/v3_app.js) проверяет его наличие при сборке очереди качества (`suspicious_heads`), и та же строка попадает в 700+ предсобранных страниц. Жёсткое падение по умолчанию блокировало бы слияния на корректном коде.

Намеренное вхождение глушится маркером **в той же строке**:

```js
if (rawHead.includes("<U+FFFD>")) queues.suspicious_heads.push(...); // encoding-guard: allow-ufffd
```

Маркер действует построчно, а не на файл, поэтому непомеченное вхождение в том же файле по-прежнему отчитывается. После разметки единственного легального случая и починки данных (issue [#187](https://github.com/gasyoun/BookIndex/issues/187)) **CI запускает обе проверки с `--strict`** — то есть U+FFFD снова жёсткая ошибка везде, кроме явно помеченных строк.

Сознательно **не** покрыто: одиночный испорченный символ (на таком пороге он неотличим от редкого легального глифа) и тексты, которые никогда не были UTF-8.

## Что нашла проверка при внедрении (31-07-2026) — и чем это кончилось

| Файл | Кол-во | Природа | Итог |
|---|---:|---|---|
| `v3_app.js` | 1 | Намеренная цитата символа в коде очереди качества | Помечено маркером `allow-ufffd` |
| `app_data.json` / `data/modules/13-languages.json` | 6 | **Настоящая потеря данных**: в цитатах книги утеряна открывающая кавычка `‘` (парная `’` на месте) | Починено, issue [#187](https://github.com/gasyoun/BookIndex/issues/187) |

Второй пункт — ровно тот класс, ради которого проверка и переделывалась: старый детектор его не видел.

**Происхождение порчи, вопреки первой гипотезе.** Сначала предполагалось, что символы пришли из конвейера расшифровок и вернутся при следующей регенерации. Проверка истории это опровергла: испорченные цитаты присутствуют в `app_data.json` начиная с самого первого коммита корпуса (`964283105`, 14-04-2026), а строки `Rauhbank` / `Bratpfanne` не встречаются ни в `data/imports/`, ни в `pipeline/`. Это цитаты **книги** (`occurrences.mumintroll.contexts`), а не лекций, и внутрирепозиторного пути, который мог бы их пересоздать, нет. Поэтому правка данных — полное исправление, а не временная заплатка. Файлы `src/content/*.md` — экспорт из `app_data.json` ([scripts/export_app_data_to_markdown.mjs](https://github.com/gasyoun/BookIndex/blob/main/scripts/export_app_data_to_markdown.mjs)), их затронутые копии поправлены тем же проходом.

Кавычка восстановлена по конвенции самого корпуса: глоссы оформляются как `‘…’` (в `app_data.json` 32 левых и 98 правых одинарных кавычек), и все шесть вхождений имели вид `— <U+FFFD>текст’` — то есть потеряна ровно открывающая.

## Прежнее решение: ftfy

`ftfy` — канонная библиотека для моджибейка в Python, и её основной приём тот же самый круговой прогон. Замер на фикстурах из [tests/unit/test_check_encoding.py](https://github.com/gasyoun/BookIndex/blob/main/tests/unit/test_check_encoding.py), ftfy 6.3.1, функция `ftfy.badness.is_bad`:

| Класс порчи | ftfy 6.3.1 | Эта проверка |
|---|---|---|
| UTF-8 как Latin-1 / CP1252 | ловит | ловит |
| UTF-8 как CP1251 | ловит | ловит |
| Двойное UTF-8 | ловит | ловит |
| U+FFFD | ловит | предупреждает |
| UTF-8 как KOI8-R | **пропускает** | ловит |
| UTF-8 как CP866 | **пропускает** | ловит |
| UTF-8 как Mac Cyrillic | **пропускает** | ловит |

Три из шести нужных классов ftfy не закрывает: её таблицы кодировок построены вокруг Latin-1/Windows-125x/MacRoman/CP437. Ради половины требования тянуть в CI новую зависимость (сейчас в [requirements.txt](https://github.com/gasyoun/BookIndex/blob/main/requirements.txt) единственный пакет — `jsonschema`) не имеет смысла, поэтому круговой прогон реализован здесь по явному списку кодеков.

## Как пользоваться

```sh
python scripts/check_encoding.py                       # ядро: v3_template.html, v3_app.js, app_data.json
python scripts/check_encoding.py README.md docs/*.md   # документация
python scripts/check_encoding.py --strict <файлы>      # предупреждения = ошибки (режим CI)
python scripts/check_encoding.py --warn-only <файлы>   # всегда exit 0, для неблокирующих прогонов
python -m unittest discover -s tests/unit -t .         # фикстуры на все классы порчи
```

В CI ([.github/workflows/ci.yml](https://github.com/gasyoun/BookIndex/blob/main/.github/workflows/ci.yml)) выполняются три шага: проверка ядра, проверка документации и юнит-тесты.

### Документация и намеренные примеры

Markdown-файлы сканируются с вырезанными код-спанами: и блоки в тройных обратных кавычках, и инлайн-код заменяются пробелами той же длины (номера строк в отчёте остаются верными). Поэтому битый текст, приведённый в документации как пример, обязан находиться внутри код-спана — так закрыт пункт 4 фазы D2 из [docs/CLEANUP_AND_UI_ROADMAP.md](https://github.com/gasyoun/BookIndex/blob/main/docs/CLEANUP_AND_UI_ROADMAP.md).

## Смежная проверка

В [scripts/issue_quality_guard.py](https://github.com/gasyoun/BookIndex/blob/main/scripts/issue_quality_guard.py) живёт более лёгкий вариант детектора для текстов из GitHub API (тела issue и комментариев, а не файлы). Он намеренно оставлен отдельным: у него другой вход, другие пороги и своя проверка шаблона.

# Почему у `lexicon` и `lexicon_reverse` разные счётчики

Отчёт сгенерирован скриптом
`scripts/explain_lexicon_reverse_divergence.py` (регенерация: `npm run content:divergence`).
Дата генерации фиксируется git-коммитом файла, не строкой в тексте.

## Короткий ответ

`lexicon_reverse` - это не механическое зеркало `lexicon`, а самостоятельный
обратный указатель, который курировался отдельно: у записей разные пространства
`canonical_id` (`lexicon-*` против `lexicon_reverse-*`, пересечение 0).
Поэтому равенство счётчиков никем не нарушалось - его никогда не было.
Расхождение раскладывается на два проверяемых слагаемых:

## Разложение

| Компонент | lexicon | lexicon_reverse | Δ (reverse − lexicon) |
|---|---:|---:|---:|
| Всего записей | 1367 | 1403 | +36 |
| Уникальных заголовков | 1367 | 1403 | +36 |
| Лишних записей от дублей заголовков | 0 | 0 | +0 |

Тождество замыкается: +36 + +0 = +36 (closure_ok: **true**).

Разложение считается по буквальным заголовкам (trim без прочих нормализаций): счётчики считают сохранённые записи, а пунктуация и диакритика - часть заголовка (частица `-то` и слово `то` - разные заголовки).

## Слагаемое 2: разный дубляж общих заголовков

Общих заголовков с разной кратностью: **0**.
При буквальном тождестве расхождений кратности нет: дубли внутри каждого указателя отсутствуют. Дубли, которые видно в данных, появляются только при нормализации без диакритики (см. ниже): одна и та же словоформа хранится с ударением на разных слогах (`doet` / `döet`) - это разные записи, а не дубляж.

## Взгляд рантайма (нормализация без диакритики)

Приложение сопоставляет заголовки через `normalizeHeadForMatch` (v3_app.js: NFD, снятие диакритики, ё→е, регистр и пунктуация игнорируются), когда наследует контексты `lexicon` в записи `lexicon_reverse`. В этом представлении внутри каждого списка есть «дубли» - записи одного лексема с ударением на разных слогах (`doet` / `döet`):

- Уникальных заголовков: lexicon - 1247, lexicon_reverse - 1275 (Δ +28);
- лишних записей от таких «дублей»: lexicon - 120, lexicon_reverse - 128 (Δ +8);
- сумма: +28 + +8 = +36 - расхождение то же самое, просто часть краевых записей и часть «дублей» перераспределяются между слагаемыми.

## Сопутствующая структура

- Записей с `note` (OCR-заглушки требуют сверки): lexicon - 0, lexicon_reverse - 11.
- Записей с `needs_review: true`: lexicon - 11, lexicon_reverse - 7.
- Категории: lexicon - lat, rus, tech; lexicon_reverse - lat, rus, tech.
- Взгляд рантайма: из reverse-only заголовков 8 совпадают с каким-либо заголовком `lexicon` по нормализации `normalizeHeadForMatch` (частица `-то` ↔ слово `то`), то есть для рантайм-наследования это тот же лексемный материал; на хранимые счётчики эта нормализация не влияет.

## Что из этого следует

1. Расхождение счётчиков - свойство двух независимо курируемых указателей, а не дефект сборки: CI-гейт синхронизации `app_data.json` ↔ `data/modules/` проверяет байтовую целостность, а не равенство этих двух списков.
2. Существенный хвост - reverse-only заголовки-заглушки (40 шт., у 11 стоит явная пометка о сверке с источником). Их разбор - контентная работа из очереди `npm run content:audit` (см. `RESULTS_LOG.md`, coverage-drain), а не задача этого скрипта.
3. Отчёт идемпотентен: скрипт только читает `app_data.json`.

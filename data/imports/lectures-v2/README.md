# lectures-v2 — корпус расшифровок лекций (C1)

Таймкодированный текстовый корпус расшифровок видеолекций А. А. Зализняка —
сырьё для будущего II тома «Популярных лекций для юношества» и для приложения
BookIndex. Это **отдельный корпус**, он НЕ вливается в `app_data.json` напрямую
(191 расшифровка × ~10 тыс. слов раздула бы единый артефакт): сюда складывается
текст, из него трек C3 извлекает сущности, которые уже идут в `app_data.json`
через `scripts/import_source.py`.

## Что здесь

| Путь | Что это |
|---|---|
| [`transcripts/<video_id>.json`](transcripts/) | Одна расшифровка: сегменты `{t, text}` с таймкодами, провенанс-стадия, источник. Ревьюируемо. |
| [`index.json`](index.json) | Индекс корпуса: список расшифровок, статистика по стадиям. |
| `raw/` | Скачанные `.docx`/`.srt` (не в git — перекачиваются скриптом). |
| [`status.json`](status.json) | Состояние корпуса. |

## Как собирается

```sh
python scripts/ingest_transcripts.py            # все доступные расшифровки
python scripts/ingest_transcripts.py --limit 3  # smoke (первые N)
python scripts/ingest_transcripts.py --id <yt>  # одна по youtube id
python scripts/ingest_transcripts.py --offline  # пере-извлечь из raw/ без сети
```

Источник правды о том, *какие* расшифровки есть и на какой они стадии вычитки —
[`data/video_pipeline.json`](../../video_pipeline.json) (поле `links.text` →
публичная ссылка Яндекс.Диска, поле `stage` → стадия). Скрипт резолвит публичную
ссылку, скачивает `.docx`/`.srt`, извлекает таймкодированные сегменты и пишет JSON.

## Формат записи

```jsonc
{
  "schema": "lecture_transcript/1",
  "video_id": "H6RAja4HOzs",          // совпадает с video_catalog.id
  "title": "...",
  "youtube_url": "https://youtube.com/watch?v=...",
  "review_stage": "read1",             // провенанс из video_pipeline.json
  "review_stage_label": "первая читка",
  "source": { "link": "<ячейка>", "links": ["..."], "file": "...docx",
              "provider": "yandex-disk-public", "sibling_files": [...] },
  "stats": { "segments": 48, "timecoded_segments": 48, "words": 5146,
             "duration_covered_sec": 2890 },
  "segments": [ { "t": 67, "text": "..." }, ... ]   // t = секунды от начала видео
}
```

Многочастные лекции (в ячейке несколько ссылок) склеиваются; у сегментов
появляется поле `part` (таймкоды внутри каждой части — свои).

## Куда это идёт

1. **B3.2 — глубокие ссылки на видео** `?t=<сек>` строятся прямо из
   `segments[].t`. Ручная разметка глав YouTube не нужна.
2. **C3 — извлечение сущностей**: имена/топонимы/языки/термины с привязкой к
   минуте лекции; кандидаты идут в `app_data.json` через `import_source.py`.
3. **KWIC по корпусу лекций**: поиск термина → минута в лекции.

## Заметки по данным (на момент C1)

- **Таймкоды уже есть в тексте.** Редакторы сохранили маркеры `ЧЧ:ММ:СС` в
  `.docx` — отсюда и сегментные таймкоды без отдельной разметки.
- **Ударения сохранены** (сковорода́, побе́да) — критично для лингвистического
  корпуса; извлечение их не теряет.
- **Ячейка `links.text` — свободный текст.** Иногда несколько ссылок и
  комментарии («Вычитано, начиная с 01:01:53: …»). Скрипт вытаскивает все
  Яндекс-URL и качает каждую часть.
- Провенанс-стадии видны читателю; «автотранскрибация» ≠ «вычитано» — стадия
  честно отражает готовность текста.

## Правила

- Не редактировать `transcripts/*.json` вручную — перегенерировать скриптом.
- Полнотекст публичен (видео и так открыты на YouTube; решение владельца).
- Этот корпус — НЕ «книга» в смысле `import_source.py`; через `--merge` он не
  идёт. Через merge идут только сущности, извлечённые в C3.
